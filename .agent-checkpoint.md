## Deviations / judgment calls (all behavior-neutral)

1. **No re-export from `@dragonwake/shared`:** web app has no dependency on that package (only `apps/server` does; `apps/web/package.json` was off-limits). Types stay locally defined in `lib/types.ts` with a pending-dedup comment. Adding `"@dragonwake/shared": "workspace:*"` to web deps would enable the re-export later.
2. **`canAfford`/`unitTrainCost` live in `lib/format.ts`** — they are pure helpers but not formatters; the dictated layout had no other home without creating extra files.
3. **Derived memos moved into views:** `startUnits` memo → CastleView, `stackUnits` memo → RealmView; `rates`, `mapW/mapH`, `selectedInfo` computed inside the views that render them; `tileAt(x,y)` became a module-level pure fn `tileAt(mapData, x, y)` in RealmView. Same inputs, same output.
4. **Loaders vs actions split:** fetch-and-set loaders stayed in `useGame` (the sim-events poll effect calls `loadReports` directly, preserving original effect structure); `run()`-wrapped mutations + `logout` went to `useGameActions(deps)` via a deps object (no context, no new libraries).
5. **Named previously-inline shapes** (`TutorialState`, `DailyQuest`, `Sovereign`, `ResearchDef`, `AllianceInfo`, `ChatMessage`, `AllianceSummary`, `MapFocus`, `FactionMeta`) to make props explicit across files.
6. **Nothing moved cleanly failed** — no logic was rewritten; all JSX/handlers moved verbatim (72/72 className expressions identical after whitespace normalization; spot-checked `toast-stack`, `bar`/`bar-fill`, `tile-detail card-inset`, `shell faction-brine|ash|sky|moss`, `tabs`/`active`/`badge`).
7. `ui/icons.tsx`, styles, main.tsx, server/packages untouched. `main.tsx` still does `import { App } from "./App"`.
